# 0013. MVP 1.3 — Symbol catalog & default subscriptions

Date: 2026-08-31

Milestone: [MVP 1.3 – Symbol catalog & default subscriptions](../roadmap.md)

## What shipped

The milestone's only issue, #159 (raised during MVP 1.2's design discussion but deliberately deferred, per retro 0012), closed via one PR (#162):

- **`contracts.SymbolCatalog`** — a new shared record (`symbols`, `majors`) with `ALL_SYMBOLS` (14 pairs, up from 3) and `MAJORS` (6 pairs) as public static constants, plus a `defaultCatalog()` factory. This replaces three independently hardcoded tradable-symbol lists: `market-data-service`'s `BASE_PRICES` map, `trading-service`'s `KNOWN_SYMBOLS` validation set, and the frontend's `PriceGrid.tsx` `KNOWN_SYMBOLS` constant. A fourth, previously unflagged copy turned up while implementing — `gateway`'s own `SdpWebSocketHandlerIT` test double, `FakeTradingService`, reimplemented `trading-service`'s validation independently — fixed the same way.
- A **domain-shaping decision was flagged before implementing** (per `ship-issue`'s standing instruction): the issue's own framing ("single source of truth in market-data-service", "a symbol-discovery mechanism") could mean either a runtime RabbitMQ broadcast from `market-data-service` at startup, or a compile-time shared constant in `contracts/` (the module all three backend services already depend on). Asked, and the shared-constant approach was chosen — see [ADR 0029](../decisions/0029-shared-symbol-catalog.md) for the full reasoning, including why the broadcast option would have reintroduced the exact `@PostConstruct`-before-channels-ready race [testing.md](../testing.md) already documents.
- `gateway`'s `SdpWebSocketHandler` sends a new `SYMBOLS` envelope once, immediately after `HELLO`, built directly from `SymbolCatalog.defaultCatalog()` — no RabbitMQ round trip.
- `market-data-service`'s `BASE_PRICES` keeps its own literal seed-price map (a seed price is that service's own concern, not part of "which symbols are tradable"), but a static assertion now fails fast if its key set ever drifts from `SymbolCatalog.ALL_SYMBOLS`.
- `PriceGrid.tsx` no longer hardcodes any symbol list: on receiving `SYMBOLS`, it sends `SUBSCRIBE` for each symbol in `majors` only (not the full `symbols` list) and `UNSUBSCRIBE`s the same set on unmount — replacing "subscribe to everything known" with a fixed, config-in-code default.
- [ADR 0029](../decisions/0029-shared-symbol-catalog.md) written during implementation; `docs/protocol.md` gained a `SYMBOLS` entry; [ADR 0013](../decisions/0013-subscription-default-nothing-until-subscribed.md)'s Consequences section annotated to point at ADR 0029 for the duplication risk it originally flagged and deferred.

## Bugs and gotchas found

- **No automated test actually asserted the `SYMBOLS` message's existence, ordering, or payload shape** — found during this retro's re-verification, not during `ship-issue`. `PriceGrid.test.tsx` tests that the frontend reacts correctly *given* a `SYMBOLS` envelope, and `sendsHelloEnvelopeOnConnect` proves `HELLO` arrives, but nothing on the backend proved the gateway actually sends `SYMBOLS` right after `HELLO` with the expected catalog — only the two live walkthroughs above exercised that. Fixed in this retro: a new `sendsSymbolsEnvelopeRightAfterHello` test in `SdpWebSocketHandlerIT` (gateway integration tests: 20 → 21) asserts both the ordering (`HELLO` then `SYMBOLS` as the connection's first two frames) and that the payload matches `SymbolCatalog.ALL_SYMBOLS`/`MAJORS` exactly. This is the same category of gap retro 0001's postscript and this skill's step 2 exist to catch — a feature that works live and has adjacent test coverage on both sides, but no test pinning the two together.
- No other new bugs found; both `ship-issue`'s original implementation and this retro's fresh re-verification passed without surprises on the first attempt of each documented run path.
