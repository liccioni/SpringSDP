# 0011. MVP 1.1 — Session resilience

Date: 2026-08-25

Milestone: [MVP 1.1 – Session resilience](../roadmap.md)

## What shipped

The milestone's only issue, #128 (a gateway process swap with a live Redis-backed session could enter an infinite OAuth2 redirect loop), closed via one PR:

- **Single shared WebSocket connection for the whole app** (PR #153): every component (`Greeting`, `PriceGrid`, `TradeBlotter`, `ExecutionConfirmation`) used to call `connect()` and open its own `WebSocket` — up to four concurrent handshakes against the same session on one page load. `socket.ts` now owns one connection; components call `subscribe(type, handler)`/`send(message)` instead.
- **Bounded retry-with-backoff before the login redirect**: a handshake that closes before ever opening is retried up to 3 times (300ms, then 900ms) before falling back to `/oauth2/authorization/keycloak`, instead of redirecting on the very first failure.
- **[ADR 0027](../decisions/0027-single-shared-socket-with-bounded-retry.md)** records the decision and its scope boundary: this doesn't change any backend/`ReactiveRedisSessionRepository` code. Issue #152 (filed mid-investigation, see below) names a specific suspect — a Spring Security session-fixation race — but that wasn't root-caused or fixed here; what shipped removes the concurrent-handshake trigger and adds resilience against the remaining transient failure, converting an infinite loop into a bounded, self-recovering retry.
- Two bugs in the fix's own test suite, found by CI rather than locally, closed inline within the same PR (see below): `resetForTests()` not clearing subscribed handlers, and `TradeHistoryDatasource` having no way to stop responding to AG Grid after its owning component unmounts.

## Verified

- Backend, from a clean `main` (fresh pull, no cache): `./gradlew clean test integrationTest` in `gateway` (38 unit + 19 integration) and `trading-service` (15 unit + 17 integration), `./gradlew clean test` in `market-data-service` (3 unit) — all green, same counts as retro 0010's baseline (this milestone touched no backend code).
- Frontend: `npm run test:unit` (46 tests, up from 41 - the destroy()-guard test plus retry-mechanics coverage) and `npm run test:integration` (1 test) — all green.
- Live, through **both** README run paths this time — the "Without Docker" path is what actually reproduces #128, so it had to be the real check, not the Docker Compose path alone:
  1. `./startUpDocker.sh`, logged in as `trader1` via the real Keycloak login page, confirmed `Hello, trader1!` and live price ticks.
  2. `docker stop`'d the `gateway` container, ran `cd gateway && ./gradlew bootRun` in its place (the exact repro from #128's issue body), reloaded the frontend tab with the still-live session cookie.
  3. Result: the tab reconnected cleanly — `Hello, trader1!`, live price ticks, no redirect loop — and a full BUY trade executed and appeared in the blotter, confirming the fix doesn't just avoid the loop but leaves the app fully usable afterward.
  4. As in PR #153's own verification, the specific `IllegalStateException: Session was invalidated` server-side race didn't trigger on this run either (consistent with the issue's own account of it being intermittent) - the retry-then-recover path itself still isn't live-confirmed, only the no-crash/no-loop path and `socket.test.ts`'s `connection retry` suite (a controllable fake socket) covering the retry mechanics directly.

## Bugs and gotchas found

- **CI caught a flake in the fix's own test that local runs didn't**: `TradeBlotter.test.tsx`'s debounce test intermittently got 3 `GET_TRADE_HISTORY` requests instead of 2. Root cause: the single-shared-connection design (this milestone's whole point) means a stale `TradeHistoryDatasource` from an *earlier, properly unmounted* test's component can still have AG Grid's own internal row-model machinery call its `getRows()` late (a real, if rare, ag-grid/jsdom timing gap) - and now that call finds a *live* shared socket to actually send over. Under the old per-component-socket design the same stray call hit an already-closed `WebSocket` and went nowhere. Fixed with a `destroy()` guard on `TradeHistoryDatasource`, called from `TradeBlotter`'s unmount cleanup. Reproduced locally at roughly 1-in-20 to 1-in-30 runs - a single run essentially never catches it, which is exactly why it reached CI before it was found locally. Durable lesson added to [docs/testing.md](../testing.md)'s Known gotchas.
- **A second, related gap in the same fix**: `resetForTests()` reset the connection but never cleared `handlersByType`, so a handler from an earlier (properly unmounted, per `setupTests.ts`'s global `cleanup()`) test's subscription could theoretically still be registered when a later test's connection started dispatching - fixed alongside the `destroy()` guard, same PR.
- Both gotchas above are consequences of the same architectural trade-off ADR 0027 makes explicit (one shared resource instead of one-per-component) - not new decisions of their own, so no separate ADR.
- Issue #152 (scope trade delivery per session — `EventBus` broadcasts every trade to every connected user) surfaced while investigating #128, unrelated to it, and named a specific suspected root cause for #128 itself (a Spring Security session-fixation race) that this milestone didn't pursue. Filed as unscheduled backlog, not part of this milestone's own scope.

## Deviations from plan

- The milestone's own framing (CLAUDE.md, roadmap.md) called this "root-cause and fix." What shipped is honest about not doing the former: [ADR 0027](../decisions/0027-single-shared-socket-with-bounded-retry.md) explicitly states the exact trigger inside `ReactiveRedisSessionRepository` remains unconfirmed. The fix removes the concurrency that made the race far more likely to trigger and adds bounded retry so a transient failure recovers instead of looping - a defensible scope cut for a single-maintainer project, but a real, disclosed gap rather than a completed root-cause investigation. If #128's underlying Redis-session race - or issue #152's suspected session-fixation cause - ever resurfaces as an actual symptom again, that's the signal to open a new, narrower backend-focused issue rather than reopening #128.
- Unlike retro 0010 (which couldn't get past #128 on the "Without Docker" path to verify anything else), this retro's own "Without Docker" pass completed the *entire* login → trade → blotter flow post-swap - the first time in two retros that path has gone all the way through without hitting an unfixed bug.
