## Verified

- Backend: `./gradlew clean test integrationTest` from a clean `main`, no cache — all unit and WebSocket integration tests pass.
- Frontend: `npm run test:unit`, `npm run test:integration`, `npm run lint`, `npx tsc -b --force` from a clean `main` — all pass.

This is what caught the #7 gap below — automated tests and green CI on individual PRs would not have.

## Bugs and gotchas found

- **Real bug**: `TradeService`'s `Sinks.many().multicast().onBackpressureBuffer()` defaulted to `autoCancel=true`, which terminated the sink once its last subscriber cancelled. Every WebSocket connection subscribes to this sink and cancels on disconnect, so the very first client disconnect killed trade broadcasting for good. Fixed with `autoCancel=false` as part of #7's PR.
- **AG Grid v36 gotchas** (module registration is mandatory; the default row model needs real pixel layout that jsdom doesn't have, worked around with `domLayout="autoHeight"`) — durable home: [ADR 0009](../decisions/0009-use-ag-grid.md).
- **Testing gotcha**: `mock-socket` can leak state across sequential tests in the same file when tests reuse identical fixture data (same symbol *and* same price) — durable home: [docs/testing.md](../testing.md).
- **Missing ADRs, found by audit rather than by anyone remembering to write them at the time** — durable home: [ADR 0007](../decisions/0007-use-webflux.md)–[0010](../decisions/0010-event-driven-protocol.md) (WebFlux, raw WebSockets, AG Grid, event-driven protocol) and [ADR 0011](../decisions/0011-use-bigdecimal-for-money.md) (BigDecimal for money fields — the reasoning existed in a commit message since issue #3/#40, but never became an ADR until this retro).

## Postscript (2026-08-05, same day)

The "Verified" section above was accurate for the local dev-server path (`./gradlew bootRun` + `npm run dev`) but never actually exercised **Docker Compose** — a real gap in this retro's own verification, found immediately afterward when the user tried `docker compose up` and saw neither the price grid nor the blotter. Root cause: Compose only builds an image automatically when one doesn't exist *yet*; a `springsdp-frontend` image built once during the original hello-world work (issue #39) kept getting silently reused for the rest of MVP 0.1, serving a stale bundle. This exact wrong assumption — that Compose "rebuilds the frontend automatically" — had been asserted in [ADR 0006](../decisions/0006-hello-world-walking-skeleton.md) itself and repeated in the README ever since. Both are now corrected (ADR 0006 via an inline correction note, the README via `docker compose up --build`). The README's "Without Docker" commands were also wrong (`./gradlew -p backend ...` from the repo root, where no `./gradlew` exists — only `backend/gradlew`) and are fixed alongside.

Lesson for the next `milestone-retro` run: "verify live" (step 2) should mean *every* documented way of running the app, not just whichever one is fastest to iterate on locally.
