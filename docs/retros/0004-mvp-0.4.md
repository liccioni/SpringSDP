# 0004. MVP 0.4 — Persistence

Date: 2026-08-07

Milestone: [MVP 0.4 – Persistence](../roadmap.md)

## What shipped

All 4 issues in the MVP 0.4 milestone, across 3 merged PRs:

- PostgreSQL + R2DBC connectivity, with connection pooling deliberately disabled to keep the plain unit-test tier and CI's `./gradlew test` job free of any live-database dependency (#21, PR #70).
- Trade history persisted via R2DBC, replacing the unused in-memory blotter list entirely; `GET_TRADE_HISTORY`/`TRADE_HISTORY` added as new envelope types (not a new endpoint, per ADR 0010) for querying it; Testcontainers adopted for backend integration tests in the same PR, since #22's own tests — and the pre-existing `CREATE_TRADE` tests — needed a real database to stay CI-safe once persistence became real (#22 + #34, PR #71).
- The frontend now requests trade history on connect and merges it with the live `TRADE_CREATED` stream by id, so a reconnect or a full backend restart repopulates the blotter instead of starting empty (#23, PR #72).

## Verified

- Backend: `./gradlew clean test integrationTest` from a clean `main`, no cache — 20 tests (13 unit, 7 integration), all passing, integration tier running against a real Testcontainers-managed Postgres.
- Frontend: `npm run test:unit`, `npm run test:integration` from a clean `main` — 21 tests, all passing.
- Live, through **both** documented run paths:
  - Docker Compose (`./startUpDocker.sh`, fresh image build): created a trade, confirmed it in the blotter, then queried the `trades` table directly via `psql` to confirm it's actually persisted, not just broadcast. Separately, created another trade, ran `docker compose restart backend` (wipes the in-memory JVM/EventBus entirely, not just a page reload), reloaded the frontend, and confirmed the blotter still showed it — the actual proof of this milestone's "restart recovery" premise.
  - Local dev servers against the same Docker Compose Postgres (`docker compose up -d postgres` then `./gradlew bootRun` + `npm run dev`, per the README's "Without Docker" section, updated in #21): same history correctly reflected, price ticks streaming.

## Bugs and gotchas found

- **Real bug, caught by a read-after-write test, not by `save()`'s return value**: `Trade`'s app-assigned UUID `id` made Spring Data R2DBC's default "is this new" check treat every `save()` as an `UPDATE` instead of an `INSERT`. The `UPDATE` matched zero rows — not an error — and `save()` still returned the entity as if it had worked, so nothing being in the table was completely silent. Found by writing a throwaway diagnostic test that did `save()` then immediately `findById()` in the same test, rather than trusting `save()`'s return value alone. Fixed with `Persistable<String>`/`isNew() = true` (correct here since trades are append-only, not a workaround). Durable home: [docs/testing.md](../testing.md).
- **A second, independent eager-connection mechanism, found right after fixing the first one** (#21's connection-pooling fix): `spring.sql.init.mode: always` runs `schema.sql` at context startup regardless of connection pooling, which would have made `SdpApplicationTests` (the only plain-unit-tier `@SpringBootTest`, no database) require a live Postgres just to load the Spring context. Fixed with a `@TestPropertySource` override to `never` on that one test class.
- **GitHub Actions had a major, hours-long outage** (webhook delivery throttled to ~15%) spanning most of #22/#23/#34's PR review. This repo's branch protection (`enforce_admins: true`) meant even an admin merge couldn't bypass the required checks — there was no forced-merge path. The accepted fallback (running the exact CI steps locally, merging once a real run genuinely completed green) only worked once an actual GitHub Actions run managed to complete; a PR's webhook event dropped during the outage doesn't replay automatically once resolved, and needed an empty-commit push to retrigger. Durable home: [docs/workflow.md](../workflow.md).

## Deviations from plan

- **#34 (Testcontainers) was folded into #22's PR rather than shipped standalone first**, after discovering mid-implementation that #22's own tests — and the pre-existing `CREATE_TRADE` integration tests — would fail in CI without a real database once persistence became real. #34's own issue text was scoped to "the R2DBC/persistence integration tests introduced in this milestone," which only exist once #22 introduces them, so a standalone #34 PR first would have had nothing concrete to test against. Flagged to @liccioni before proceeding, same standard as a domain-shaping decision.
- Two domain-shaping decisions were flagged and answered up front, both recorded in [ADR 0015](../decisions/0015-trade-history-db-backed-schema-sql.md): schema management via `schema.sql` over Flyway (simplest for a first table), and retiring the in-memory blotter entirely rather than keeping it alongside the database (it had zero production callers).

No other structural deviations.
