# 0010. MVP 1.0 — Trade history at scale

Date: 2026-08-21

Milestone: [MVP 1.0 – Trade history at scale](../roadmap.md)

## What shipped

All four issues in the MVP 1.0 milestone, plus two of the three bugs filed live-verifying MVP 0.9, across seven merged PRs:

- **Scope the milestone** (PR #134) and a **design spec** for the query engine (PR #135, issue #130).
- **Cursor-paginated, filterable, sortable trade history query engine** (#130, PR #136): new `TradeHistoryQuery`/`TradeSort`/`TradeFilter`/`TradeHistoryPage` contract types; a base64url-encoded `{ts, id, sv}` keyset cursor; a new `idx_trades_timestamp_id` index; `TradeHistoryQueryService` built directly on R2DBC's `DatabaseClient` (not `TradeRepository`) with an allow-listed set of sort/filter columns bound as parameters, never interpolated. [ADR 0026](../decisions/0026-cursor-paginated-trade-history.md).
- **Generic `correlationId` on the `Envelope` + gateway relay** (#131, PR #137): lets more than one `GET_TRADE_HISTORY` be in flight per connection, each `TRADE_HISTORY` reply echoing back the request's own id.
- **AG Grid Infinite Row Model + correlation-aware datasource** (#132, PR #147): `TradeHistoryDatasource` implements `IDatasource.getRows()`, maps AG Grid's sort/filter model onto `TradeHistoryQuery`, and a live `TRADE_CREATED` now triggers a debounced `refreshInfiniteCache()` instead of local-state merge.
- **ADR + `docs/protocol.md` rewrite** (#133, PR #148) for the new payload/reply shapes.
- **Two bugs found live-verifying MVP 0.9, closed within this milestone**: #126 (logout 500s on an already-expired session, PR #146) and #127 (audit trail/`HELLO` recording the Keycloak `sub` UUID instead of the username, PR #149).
- **Three bugs found live-verifying this milestone's own work, closed inline**: #138 (one bad/slow WebSocket message silently killed the whole connection, PR #140), #139 (the blotter's Time column used a text filter instead of a date filter, PR #141), and #144 (the blotter never actually loaded history on connect — sent `GET_TRADE_HISTORY` with no payload against a query engine that now requires one, PR #145).

## Verified

- Backend, from a clean `main` (fresh pull, no cache): `./gradlew clean test integrationTest` in `gateway` (38 unit + 19 integration) and `trading-service` (15 unit + 17 integration), `./gradlew clean test` in `market-data-service` (3 unit) — all green.
- Frontend: `npm run test:unit` (41 tests) and `npm run test:integration` (1 test) — all green.
- Live, through the **Docker Compose** path (`./startUpDocker.sh`, rebuilding every image fresh): logged in as `trader1`, confirmed the `HELLO` greeting correctly reads "Hello, trader1!" (not the `sub` UUID — #127's fix holds), executed several trades and watched them land in the blotter via the live-refresh path, typed a non-matching-then-matching symbol into the floating filter and confirmed the grid narrowed to a server-side-filtered result set (not a client-side one — verified by the round-trip latency and by checking only the requested symbol's rows returned), and sorted the Time column ascending/descending and confirmed the order flipped correctly.
- The **"Without Docker"** path was attempted but not usable as a second independent confirmation of this milestone's own story — see below; MVP 1.0's story is confirmed via the Docker Compose pass and the automated integration test suite (`TradeHistoryQueryServiceIT`'s keyset-pagination-across-two-pages case in particular covers exactly what the browser pass couldn't re-confirm end to end).

## Bugs and gotchas found

- **#138/PR #140 — one bad or slow WebSocket message could silently kill the whole connection.** Found live-testing #131: the blotter's `GET_TRADE_HISTORY` (still sent with no payload at that point, a gap not closed until #144/PR #145) NPE'd in `trading-service` and timed out after 10s; that `TimeoutException` propagated through `SdpWebSocketHandler.handleIncoming`'s `flatMap` and closed the connection outright — looked exactly like a filter bug, was actually a dead connection. Fixed with a `Mono.defer(...)` + `.onErrorResume(...)` error boundary per message. Durable lesson added to [docs/testing.md](../testing.md)'s Known gotchas (it wasn't there before this retro).
- **#128 reproduced again, unchanged, on the "Without Docker" path** — a gateway process swap while a browser tab holds a live Redis-backed session enters an infinite OAuth2 redirect loop (`ReactiveRedisSessionRepository` invalidation → `socket.ts` redirects to Keycloak → Keycloak's still-live SSO session silently re-authenticates → redirects straight back → fails again). This is the *second consecutive* milestone retro to hit this exact bug on this exact path (see retro 0009's own note predicting this). PR #137's own body independently flagged "a pre-existing, unrelated dev-mode flake... same family as backlog bug #128" during its own live verification — corroborating evidence that this is a real, recurring gap, not a one-off. Not fixed here (root-causing the Redis session race remains out of scope for this milestone, same as 0009's call), but now confirmed twice running. Given the pattern, #128 is worth prioritizing into an actual milestone rather than staying indefinitely unscheduled backlog.
- Confirms retro 0009's own prediction: *"the native path keeps finding its own class of issue every time it's actually exercised."* Two retros running, the native path has surfaced a real bug both times (#128 both times, in fact) while the Docker Compose path has not. That's a strong enough signal that the "Without Docker" path deserves its own lighter-weight smoke check outside of milestone retros too, not just a per-retro afterthought.

## Deviations from plan

- The "Without Docker" verification pass didn't get to independently re-confirm this milestone's filter/sort/pagination story — it hit #128's redirect loop before any of that could be exercised, the same shape of deviation retro 0009 recorded for MVP 0.9. The Docker Compose pass plus the automated integration suite (which exercises keyset pagination, every filter operator, and both sort directions directly against a real Postgres) is this retro's evidence that the story holds up; unlike 0009, this milestone's actual backend logic is also covered by tests that don't depend on either browser path at all.
- Three bugs surfaced and were fixed *inline*, mid-milestone (#138, #139, #144) rather than being deferred to a later issue — each was a small, contained fix blocking the next issue's own live verification (a dead connection blocks confirming anything past 10s; an empty blotter blocks confirming the "today" filter; a text filter blocks confirming date-range filtering), so fixing forward was faster than filing and resuming later. Consistent with the milestone's own sequencing notes in PR #136/#137/#145's bodies.
