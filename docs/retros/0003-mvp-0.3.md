# 0003. MVP 0.3 — Reactive architecture

Date: 2026-08-06

Milestone: [MVP 0.3 – Reactive architecture](../roadmap.md)

## What shipped

All 4 issues in the MVP 0.3 milestone, across 4 merged PRs:

- An internal event bus over Reactor `Sinks`, decoupling `MarketDataService`/`TradeService` from `SdpWebSocketHandler`, and fixing a latent bug where every WebSocket connection ran its own cold `Flux.interval` price generator (#17, PR #64).
- `TradeService.createTrade` converted from `Optional<Trade>` to `Mono<Trade>`, and `SdpWebSocketHandler`'s inbound pipeline converted from a fire-and-forget `doOnNext` to `flatMap`, so the WebSocket layer composes trade creation into its reactive chain instead of ignoring the result (#18, PR #65).
- Per-connection `SUBSCRIBE`/`UNSUBSCRIBE` for market data: every connection now starts subscribed to no symbols and only receives `PRICE_TICK` for symbols it explicitly subscribes to. `PriceGrid` updated to subscribe to its known symbols on connect so the app stays runnable (#19, PR #66).
- A real concurrency bug fixed in `EventBus.publish()`: concurrent producer threads (the market-data ticker thread and WebSocket connection threads both calling `publish()`) were silently dropping events, because Reactor's `Sinks.Many` requires the caller to serialize emissions and `tryEmitNext`'s failure was never checked (#20, PR #67).

## Verified

- Backend: `./gradlew clean test integrationTest` from a clean `main`, no cache — all unit and WebSocket integration tests pass (12 unit, 6 integration).
- Frontend: `npm run test:unit`, `npm run test:integration` from a clean `main` — all pass (17 unit, 1 integration).
- Live, in a real browser, against the real running backend and frontend, through **both** documented ways of running the app (per the lesson from retro 0001's postscript):
  - Docker Compose (`./startUpDocker.sh`, fresh image build from merged `main`): all three symbols streamed, and a Sell executed and appeared in the blotter. A second, separately-opened tab's trades were also visible in the same blotter — a live confirmation of the EventBus fix holding under real concurrent, multi-connection use, not just the unit test.
  - Local dev servers (`./gradlew bootRun` + `npm run dev`): same story — all three symbols streaming, a Buy executed and confirmed in the blotter. (First click attempt registered no trade — a one-off automation timing issue with the page having just loaded, not a regression; the retry succeeded cleanly and repeatably.)
  - Issue #19's own PR was additionally verified live during implementation (not just at retro time), against a temporary backend/frontend pair on non-default ports, specifically so as not to disturb the user's already-running Docker Compose stack from an earlier session.

## Bugs and gotchas found

- **Real bug, proven and fixed**: `EventBus.publish()` dropped events under concurrent producers. Reproduced directly with a test racing 20 threads × 50 events each against the unsynchronized sink — reliably lost events on 5/5 runs. After wrapping `tryEmitNext` in a `synchronized` block, the same test passed reliably on 8/8 runs. This had been live since MVP 0.1 (`MarketDataService`'s ticker thread and any WebSocket connection thread calling `TradeService.createTrade` were always genuinely concurrent), just never caught because low-concurrency manual testing rarely triggers the race. Durable home: [docs/testing.md](../testing.md) — the reproduction technique (N racing threads via `ExecutorService` + `CountDownLatch`) is documented there for reuse if more `Sinks`-backed state is added later.
- **Process gotcha, this session**: an active `/goal`'s stop-hook inferred that "complete" implied merging a PR, twice, contradicting the ship-issue/milestone-retro skills' explicit "merge only when asked, per-PR" policy — and once, after the user had just explicitly answered "leave it open." Resolved both times by asking the user directly with a fresh question rather than treating the hook's inference as authorization. Suggest making this explicit in `ship-issue`/`milestone-retro`'s existing merge-policy text: an active goal's phrasing is not the user granting per-PR merge authorization, even when a goal's stop condition is pushing toward it.
- No stale-Docker-image gap this time (the retro 0001 lesson) — `startUpDocker.sh` was used for the live verification, which always rebuilds both images.

## Deviations from plan

One domain-shaping decision was flagged and answered before implementation, not deferred to a PR-body note, since it had real, lasting consequences for the wire protocol and the frontend:

- #19 left open what a connection receives before it sends any `SUBSCRIBE`. Asked the user up front; chose "nothing until subscribed" (matching the issue literally) over "everything, narrowed by unsubscribe" (backend-only, smaller PR) — see [ADR 0013](../decisions/0013-subscription-default-nothing-until-subscribed.md) for the full reasoning. This is the same class of decision as [ADR 0011](../decisions/0011-use-bigdecimal-for-money.md)'s money-type call, and got the same up-front-question treatment rather than a silent default.

No other structural deviations. #20's scope stayed to the one real gap found (`EventBus`); the rest of the in-memory state named in the issue (`TradeService.blotter`, `MarketDataService.midPrices`, `SdpWebSocketHandler.subscribedSymbols`) was audited and confirmed already safe, not rewritten speculatively.
