# 0007. MVP 0.7 — Service topology & messaging

Date: 2026-08-12

Milestone: [MVP 0.7 – Service topology & messaging](../roadmap.md)

## What shipped

All issues in the MVP 0.7 milestone, across 7 merged PRs, splitting the monolith into three services connected via RabbitMQ/Spring Cloud Stream through a strangler-fig migration (nothing ever stopped running):

- **Docker Compose network segmentation** (#88, PR #101): `public`/`internal` Compose networks, RabbitMQ container added. ADR 0021.
- **Scaffold the three services** (#89, PR #106): `gateway/`, `market-data-service/`, `trading-service/` stood up alongside the still-running monolith as bare skeletons — no broker/database/auth wiring yet, proving only that the multi-service shape boots cleanly. `contracts/` introduced as a Gradle composite build for shared wire-shape types. ADR 0022.
- **Migrate price ticks** (#90, PR #107): `market-data-service` generates `PriceTick`s onto a fanout exchange; the monolith consumes and relays onto its existing in-process `EventBus`, unchanged from the browser's perspective.
- **Migrate trade broadcasts** (#91, PR #108): `trading-service` gains real trade/audit domain logic and R2DBC/Postgres access; `TRADE_CREATED`/`TRADE_REJECTED` broadcast from there over RabbitMQ.
- **Migrate trade request/reply** (#92, PR #109): `CREATE_TRADE`/`CONFIRM_TRADE`/`CANCEL_TRADE`/`GET_TRADE_HISTORY` move to a correlation-id-based async request/reply pattern over RabbitMQ (deliberately not `RabbitTemplate`'s blocking RPC call). The monolith's `TradeService` becomes pure request/reply plumbing.
- **Migrate session-start audit** (#93, PR #110): `SESSION_STARTED` moves to a fire-and-forget fanout exchange, consumed by `trading-service`'s `AuditService`.
- **Decommission the monolith** (#94, PR #111): `LOGIN_SUCCESS`/`LOGIN_ERROR` migrate the same way; every remaining monolith package moves into `gateway/` verbatim; `backend/` is deleted entirely; docs/README/CI rewritten for the final 3-service topology.

## Verified

- Backend, from a clean `main` (fresh pull, no cache): `./gradlew clean test integrationTest` in `gateway` (14+ tests) and `trading-service` (6+ tests), `./gradlew clean test` in `market-data-service` (3 tests, no `integrationTest` task by design — no Testcontainers-backed test yet) — all green.
- Frontend: `npm run test:unit` (25 tests) and `npm run test:integration` (1 test) — all green.
- Live, through the Docker Compose path (`./startUpDocker.sh`, rebuilding every Jib image fresh): real browser login as `trader1` through Keycloak, live price ticks streaming for all three symbols, a full `CREATE_TRADE → TRADE_PENDING → CONFIRM_TRADE → TRADE_CREATED` round trip with the confirmed trade landing in the blotter, trade history loading from Postgres via `trading-service` — the entire path running through `gateway`/`market-data-service`/`trading-service` over RabbitMQ with no monolith anywhere in the request path.
- The "Without Docker" native path was not independently re-verified this retro (each of #90-#94's own PRs already live-verified against Docker Compose per their Testing notes; MVP 0.6's retro already found and fixed a native-path gap once, and nothing in MVP 0.7 changes what the native path requires beyond what README's "Without Docker" section already documents for RabbitMQ).

## Bugs and gotchas found

- **Issue #79 was mistagged with the MVP 0.7 milestone on GitHub**, even though its own issue body says "No milestone — backlog idea, not scheduled work" and `docs/roadmap.md` lists it as backlog intended for whenever `trading-service` picks it up next, not as in-scope MVP 0.7 work. This blocked treating the milestone as closed per this skill's own step 1 check. Fixed by removing the milestone tag from #79 (`gh issue edit 79 --remove-milestone`) rather than treating it as a real blocker — the drift was in GitHub's tracking, not in the roadmap or the issue's own stated intent.
- **A realm-import JSON that omits `sslRequired` defaults to Keycloak's `EXTERNAL`, not `NONE`** — a gap in `keycloak/sdp-realm.json` present since MVP 0.6 (#96/#98), invisible until a request came in over a path Keycloak didn't classify as local/loopback, surfacing as Keycloak's own "HTTPS required" error page rather than an application-level error. Found while resuming work on a machine that had pulled #111 but not yet re-run the full stack. Fixed with `"sslRequired": "none"`; documented in [ADR 0020](../decisions/0020-keycloak-oauth2-redis-session.md).
- **A `docker compose up` on a machine with a stack already running from before #94 leaves the old `backend` container running as an orphan**, squatting on port 8080 (now `gateway`'s port) until removed explicitly (`--remove-orphans` or a fresh `down`) — Compose warns but doesn't auto-clean. Compounded by a second, subtler issue: a `gateway` container already running from before this merge keeps serving its **old** image indefinitely across a plain `restart`/`up -d --force-recreate`, since recreating a container doesn't rebuild it from source — only `./startUpDocker.sh`'s Jib rebuild step does. The stale image's symptom was silent: clean startup logs, but `/oauth2/authorization/keycloak` 404'd because it was still running the pre-#94 package layout, which never had `com.sdp.config` in its component-scan root (the exact sibling-package gotcha already documented for #91). Both fixed by running `./startUpDocker.sh` properly rather than hand-rolling `docker compose` commands. Documented in [ADR 0022](../decisions/0022-service-topology.md).
- **IntelliJ's local `.idea/gradle.xml` still pointed at the deleted `backend/` as its only linked Gradle build** after pulling #111 — a one-time consequence of this issue deleting a whole linked module, not something future service additions will repeat. Relinked to `gateway/`, `market-data-service/`, `trading-service/`, and `contracts/`. Purely local, gitignored state — no durable doc home applies beyond this note.

## New skill candidates surfaced

- **A "resume work after a topology-changing merge" checklist**, distinct from `ship-issue` (which covers the PR author's own verification) and this skill (which covers milestone-close verification from a clean checkout). This retro found three environment-state issues that only bite a *second* machine/session picking up work after a merge that adds or deletes a whole service/module: a stale IntelliJ Gradle link to a deleted module, an orphaned Docker container from a deleted service still squatting on a reassigned port, and a container silently serving a pre-merge image because recreating it doesn't rebuild from source. None of these are bugs in the merge itself — #111's own live verification (a fresh `docker compose up` with `backend/` already deleted) wouldn't have caught any of them, since none exist on a machine that never had the old topology running. A short checklist (git pull; check for orphaned containers; check IDE Gradle links against current `settings.gradle` files; prefer `./startUpDocker.sh` over hand-rolled `docker compose` commands after any service-boundary change) would have caught all three immediately instead of needing live debugging.
