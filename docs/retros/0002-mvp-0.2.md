## What shipped

- A trading-terminal visual redesign of the price grid and blotter (#56, PR #57) — done before this retro's work started.

## Bugs and gotchas found

- **Real bug, caught mid-milestone**: React Testing Library's automatic `afterEach(cleanup)` never registered (Vitest `globals` is off), so renders leaked across tests in the same file. Invisible until #13 added a quantity input with a stable id/label, at which point a later test's `getByLabelText` silently resolved to an *earlier* test's stale element. Fixed in #13's PR (`src/setupTests.ts` now registers cleanup explicitly) — durable home: [docs/testing.md](../testing.md).
- **Process gotcha**: stacking issue #14's branch on issue #13's still-unmerged branch (since #14 builds directly on #13's quantity input) meant that once #13 was squash-merged, retargeting #14's PR base to `main` showed a conflict — the squash commit shares no history with #13's original commits. Resolved with `git rebase origin/main` (git recognized the content as already upstream and dropped those commits) plus a force-push. Durable home: [docs/workflow.md](../workflow.md).
- **Tooling quirk**: `gh pr edit --base`/`--body` on this repo intermittently surfaces a `GraphQL: Projects (classic) is being deprecated` error that's unrelated to the edit itself — the edit still goes through. Cost time double-checking the first time it happened. Durable home: [docs/workflow.md](../workflow.md).
- No new ADRs were needed. #14's double-click → explicit-buttons change is a UI interaction decision, not an architecture/protocol one (matches the existing ADR set's scope — tech stack, protocol shape, domain modeling — not interaction patterns), so it stays documented in its PR/commit message. #16's new `TRADE_REJECTED` event is exactly the kind of protocol extension [ADR 0010](../decisions/0010-event-driven-protocol.md) already anticipated ("a new event type is added by extending the type enumeration"), so it didn't need a fresh ADR either. #16's one real open question — broadcasting `TRADE_REJECTED` to every session instead of only the submitter — isn't a decision yet (there's no session concept to decide it against), so it's recorded as a flagged question in [docs/protocol.md](../protocol.md) rather than an ADR.

## Deviations from plan

None structural. Two domain-shaping/scope calls were made and flagged in their PRs rather than asked about mid-flight, per the standing `/goal` directive not to pause for those turns:

- #14's issue text left "replacing/complementing" the double-click flow ambiguous; went with full replacement.
- #15's issue text said "accepted (or rejected)", but #16 (validation) hadn't landed yet, so there was nothing to reject; #15 shipped only the accept path and the confirmation *mechanism*, leaving the reject path for #16 to actually add.

Both turned out to be the right calls in hindsight — #16 slotted the rejection banner into the same component #15 built, with no rework.
